# PRD — 서울·경기 아파트 실거래 대시보드

> "내 예산으로 어디 갈 수 있나?" 한 화면에서 답하는 실거주자용 대시보드

- 문서 버전: v1.0
- 작성일: 2026-08-12
- 배포 대상: GitHub Pages (`sojung-yun404/sesac-web`)

---

## 1. 배경과 목표

### 페르소나

> **30대 직장인, 실거주 목적 아파트 매매를 준비 중.**
> 모아둔 자기자본과 받을 수 있는 대출을 합쳐 예산은 대략 정해져 있는데,
> 그 돈으로 **어디까지 갈 수 있는지** 감이 없다. 서울만 고집할 생각도 없어서
> 경기도까지 같은 기준으로 놓고 비교하고 싶다.

### 핵심 질문 (이 대시보드가 답해야 할 단 하나)

**"내 예산으로 어디 갈 수 있나?"**

모든 화면과 기능은 이 질문에 대한 답을 좁혀가는 과정이어야 한다.
이 질문에 기여하지 않는 지표는 넣지 않는다.

### 성공 기준

| 지표 | 목표 |
|---|---|
| 예산 입력부터 후보 지역 확인까지 | 3초 이내, 스크롤 없이 |
| 후보 지역 → 실제 단지 목록 도달 | 클릭 2회 이내 |
| 초기 페이지 로드 | 2초 이내 (모바일 4G 기준) |
| 다루는 지역 | 서울 25개 구 + 경기 31개 시·군 (동등 취급) |

---

## 2. 사용자 스토리

1. 자기자본 3억, 대출 4억이 가능하다. **7억으로 갈 수 있는 지역**이 어디인지 한눈에 보고 싶다.
2. 서울 성북구와 경기 하남시를 **같은 기준으로** 나란히 비교하고 싶다.
3. 국민평형(84㎡)만 보고 싶고, 너무 오래된 구축은 빼고 싶다.
4. 1년 전 거래가는 지금 시세와 다를 테니 **최근 거래만** 보고 싶다.
5. 거래가 1~2건뿐인 단지는 시세를 믿기 어려우니 걸러내고 싶다.
6. 관심 가는 단지 이름으로 검색해서 **그 단지 실거래 내역**을 확인하고 싶다.
7. 지금 시장이 오르는 중인지 내리는 중인지 **월별 흐름**도 곁눈질하고 싶다.

## 3. 범위

### 포함 (v1)

- **매매 거래만** — 실거주 매수가 목적이므로 전세·월세는 다루지 않는다.
- 서울 25개 구 (보유 CSV) + 경기 31개 시·군 (국토부 API 수집)
- 기간: 2025-07 ~ 2026-06 (12개월)
- 단일 페이지 대시보드 (`dashboard.html`)

### 제외 (v1)

- 전세·월세, 전세가율 — 데이터는 있으나 핵심 질문과 직결되지 않음
- 지도 시각화 — 좌표 데이터가 없어 별도 지오코딩이 필요, v2로 유예
- 학군·교통·편의시설 — 실거래 데이터 범위 밖
- 로그인, 즐겨찾기 저장 (정적 사이트 제약)

## 4. 기능 요구사항

### F1. 예산 컨트롤 (최우선)

화면 최상단 고정. 여기가 대시보드의 입력부이자 심장.

- **자기자본** 입력 + **대출한도** 입력 → 합계가 **예산 상한**으로 자동 계산
- 대출한도는 **직접 입력이 기본**, "모르겠으면 LTV로 계산" 보조 버튼 제공
  - LTV 보조는 참고값임을 명시 (실제 한도는 지역·소득·생애최초 여부로 달라짐)
- **하한 슬라이더** 별도 제공 → 지나치게 싼 매물(하자 가능성)을 걸러냄
- 상한은 자동 계산되되 **수동 조정 가능**
- 입력값 변경 시 아래 모든 뷰가 즉시 갱신 (리로드 없음)

### F2. 지역 랭킹 표

- 서울 25구 + 경기 31시군을 **하나의 표에 동등하게** 나열
- 컬럼: 지역명 / 중위가 / 최저가 / 최고가 / 거래건수 / **예산 가능 여부 뱃지**
- **판단 기준은 중위가** — 극단적 고가·저가 거래에 흔들리지 않아 체감 시세에 가장 가까움
- 정렬: 중위가 오름차순 기본, 컬럼 클릭으로 변경
- 예산 범위 내 지역은 시각적으로 강조, 밖은 흐리게 (제외가 아니라 대비)

### F3. 월별 가격 추이 차트

- 12개월 중위가 추이를 꺾은선으로 표시
- 관심 지역 여러 개를 겹쳐 비교 가능
- 예산 상한선을 가로 기준선으로 오버레이 → "언제부터 이 지역이 예산을 넘었나"가 보임

### F4. 단지 검색 + 상세

- 아파트 이름으로 검색 (부분 일치, 한글 초성 불필요)
- 결과: 단지명 / 지역 / 평형별 중위가 / 거래건수 / 건축년도
- 단지 선택 시 해당 단지의 개별 실거래 내역 표시

### F5. 필터 (인터뷰에서 4개 모두 선택됨)

| 필터 | 기본값 | 근거 |
|---|---|---|
| **전용면적(평형)** | 84㎡대 (80~90㎡) | 국민평형. 가격 비교의 기준선 |
| **건축년도** | 전체 | 신축 선호는 개인차가 커 기본은 열어둠 |
| **거래 시기(최근성)** | 최근 6개월 | 12개월 전 가격은 현재 시세와 괴리 |
| **최소 거래건수** | 3건 이상 | 1~2건 거래로 산출한 중위가는 신뢰도가 낮음 |

## 5. 데이터

### 소스

| 지역 | 소스 | 상태 |
|---|---|---|
| 서울 25개 구 | 보유 CSV (`seoul-apt-latest.csv`, 32만 행) | 확보 완료 |
| 경기 31개 시·군 | 국토교통부 아파트 매매 실거래가 상세 API | API 키 발급 필요 |

- API: `getRTMSDataSvcAptTradeDev` (공공데이터포털)
- 예상 호출량: 31개 시군 × 12개월 ≈ 400~500회 (일일 한도 10,000건 내)

### 정적 배포를 위한 전처리

GitHub Pages는 서버가 없으므로, 27MB 원본 CSV를 브라우저에 그대로 보낼 수 없다.
Python 전처리 스크립트로 **집계된 JSON**을 미리 생성해 배포한다.

| 파일 | 내용 | 목표 크기 |
|---|---|---|
| `regions.json` | 지역별 × 평형별 × 월별 집계 (중위/최저/최고/건수) | < 300KB |
| `complexes.json` | 단지별 요약 (평형별 중위가, 건축년도, 거래건수) | < 2MB |
| `trades/*.json` | 단지 상세 조회용 개별 거래 내역 (지역 단위 분할) | 지연 로드 |

- 초기 로드는 `regions.json`만 — 랭킹표와 추이 차트가 즉시 뜬다
- `complexes.json`은 검색을 처음 쓸 때 지연 로드
- 배열 기반 구조 + 문자열 사전으로 용량 절감

### 집계 규칙

- **중위가(median)** 를 대표값으로 사용 — F2의 판단 기준과 동일
- 평형 버킷: `~59㎡` / `59~80㎡` / `80~90㎡(국평)` / `90~135㎡` / `135㎡~`
- 해제된 거래(`cdealType`)는 집계에서 제외
- 금액 단위: 만원 (원본 유지), 표시할 때만 억 단위로 변환

## 6. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 호스팅 | GitHub Pages | 고정 요구사항 |
| 프론트엔드 | Vanilla JS + HTML/CSS | 빌드 없이 Pages에 바로 배포. 규모상 프레임워크 불필요 |
| 차트 | 인라인 SVG 직접 생성 | 외부 CDN 의존 제거, 로드 속도 확보 |
| 디자인 | Montage 디자인 토큰 (기존 `index.html`과 동일) | 사이트 일관성 |
| 데이터 처리 | Python 표준 라이브러리 | 기존 `analyze.py`와 동일 기조, 의존성 없음 |

### 페이지 구성

- `index.html` — 기존 자기소개 (유지), 대시보드로 가는 링크 추가
- `dashboard.html` — 대시보드 본체 (단일 페이지)

## 7. 비기능 요구사항

- **반응형** — 모바일에서도 랭킹표와 예산 컨트롤이 사용 가능해야 함 (표는 가로 스크롤)
- **접근성** — 색상만으로 예산 가능 여부를 전달하지 않고 텍스트 뱃지 병행
- **데이터 출처 명시** — 국토교통부 실거래가 자료임을 푸터에 표기
- **면책** — 실거래 신고 자료 기반 참고용이며 실제 매물 시세와 다를 수 있음을 명시

## 8. 구현 순서

1. 서울 CSV → JSON 전처리 스크립트 (`scripts/build_data.py`)
2. 대시보드 프론트엔드 (서울 데이터로 완성)
3. 경기도 API 수집 스크립트 (`scripts/fetch_gyeonggi.py`) — API 키 확보 후
4. 경기 데이터 병합 → 재배포

> 3번이 사용자 액션(API 키 발급)에 의존하므로, 1·2번을 먼저 완성해 서울만으로도
> 동작하는 대시보드를 배포한 뒤 경기 데이터를 덧붙이는 순서로 진행한다.
