# 데이터 계약 (Data Contract)

전처리 스크립트와 프론트엔드가 공유하는 **단일 규격**. 양쪽 모두 이 문서를 기준으로 구현한다.

## 설계 원칙

GitHub Pages는 서버가 없으므로 모든 집계는 (a) 빌드 타임에 미리 계산하거나 (b) 브라우저에서 계산해야 한다.
둘을 섞어 쓴다.

- **`regions.json`** — 기본 필터 기준으로 미리 계산된 집계. 첫 화면을 즉시 그린다. (작음)
- **`trades-*.json`** — 거래 단위 원본. 사용자가 필터를 건드리거나 검색할 때 지연 로드해서
  브라우저에서 정확히 재계산한다. (큼)

이 구조 덕분에 첫 페인트가 빠르면서도, 어떤 필터 조합에서든 **근사치가 아닌 정확한 값**이 나온다.

---

## 공통 규칙

- 금액 단위는 **만원** (원본 유지). 억 단위 변환은 표시 시점에만.
- 전용면적은 **㎡ × 10을 정수로** 저장 (84.8㎡ → `848`). 부동소수점 오차 방지.
- 월 인덱스는 `meta.months` 배열의 인덱스 (0 = 가장 오래된 달).
- 해제된 거래는 **전처리 단계에서 제외**한다.
- 매매 거래만 포함한다. 전세·월세는 다루지 않는다.

## 평형 버킷

`meta.buckets` 로 제공하며 프론트엔드는 이 정의를 하드코딩하지 않는다.

| key | label | 범위 (㎡) |
|---|---|---|
| `u59` | 59㎡ 이하 | `area < 60` |
| `s60` | 60~80㎡ | `60 <= area < 80` |
| `s80` | 84㎡대 (국평) | `80 <= area < 90` |
| `s90` | 90~135㎡ | `90 <= area < 135` |
| `o135` | 135㎡ 초과 | `area >= 135` |

기본 선택은 `s80`.

## 1. `data/regions.json`

첫 화면용 사전 집계. 목표 크기 300KB 미만.

```json
{
  "meta": {
    "generated": "2026-08-12",
    "months": ["2025-07", "2025-08", "…", "2026-06"],
    "buckets": [
      { "key": "u59",  "label": "59㎡ 이하",     "min": 0,   "max": 60 },
      { "key": "s60",  "label": "60~80㎡",      "min": 60,  "max": 80 },
      { "key": "s80",  "label": "84㎡대 (국평)", "min": 80,  "max": 90 },
      { "key": "s90",  "label": "90~135㎡",     "min": 90,  "max": 135 },
      { "key": "o135", "label": "135㎡ 초과",    "min": 135, "max": null }
    ],
    "source": "국토교통부 실거래가 공개시스템",
    "datasets": [
      { "sido": "서울", "file": "trades-seoul.json", "trades": 72459 }
    ]
  },
  "regions": [
    {
      "sido": "서울",
      "name": "성북구",
      "stats": {
        "s80": {
          "all":     [98000, 40000, 215000, 1686],
          "r6":      [101000, 52000, 215000, 812],
          "r3":      [103500, 61000, 215000, 402],
          "monthly": [[95000, 120], [96500, 133], null, "…"]
        }
      }
    }
  ]
}
```

### 필드 정의

- `stats[bucketKey]` — 해당 평형 버킷의 통계. **거래가 없는 버킷은 키 자체를 생략**한다.
- `all` / `r6` / `r3` — 전체 기간 / 최근 6개월 / 최근 3개월
  - 형식: `[중위가, 최저가, 최고가, 거래건수]` (모두 만원 단위 정수)
- `monthly` — `meta.months`와 **같은 길이**의 배열. 각 원소는 `[중위가, 거래건수]`,
  거래가 없는 달은 `null`.
- `sido` 는 `"서울"` 또는 `"경기"`. 프론트엔드는 두 값을 **동등하게** 취급한다 (정렬·필터에서 차별 없음).

### 중위가 계산

정렬 후 짝수 개면 가운데 두 값의 **평균을 반올림한 정수**. `statistics.median` 사용 시에도
결과를 `round()` 하여 정수로 맞춘다.

## 2. `data/trades-seoul.json` / `data/trades-gyeonggi.json`

거래 단위 원본. 지연 로드 전용. 문자열은 사전으로 분리해 중복을 제거한다.

```json
{
  "meta": { "sido": "서울", "months": ["2025-07", "…"] },
  "regions":   ["강남구", "강동구", "…"],
  "dongs":     ["개포동", "논현동", "…"],
  "complexes": ["개포자이프레지던스", "래미안길음센터피스", "…"],
  "fields": ["r", "d", "c", "m", "a", "f", "y", "p"],
  "trades": [
    [0, 0, 1, 0, 848, 4, 2023, 138000]
  ]
}
```

### `fields` 의미 (배열 원소 순서와 1:1 대응)

| 위치 | 키 | 의미 | 예 |
|---|---|---|---|
| 0 | `r` | `regions` 배열 인덱스 | `0` → 강남구 |
| 1 | `d` | `dongs` 배열 인덱스 | `0` → 개포동 |
| 2 | `c` | `complexes` 배열 인덱스 | `1` → 래미안길음센터피스 |
| 3 | `m` | `meta.months` 인덱스 | `0` → 2025-07 |
| 4 | `a` | 전용면적 × 10 | `848` → 84.8㎡ |
| 5 | `f` | 층 | `4` |
| 6 | `y` | 건축년도 | `2023` |
| 7 | `p` | 거래금액 (만원) | `138000` → 13.8억 |

- 사전 배열(`regions`/`dongs`/`complexes`)은 **파일 단위로 독립**이다.
  서울과 경기 파일의 인덱스는 서로 호환되지 않으므로, 병합 시 각 파일을 개별로 해석한다.
- `f`(층), `y`(건축년도)가 원본에 없으면 `0`으로 채운다. 프론트엔드는 `0`을 "정보 없음"으로 처리하고
  건축년도 필터 적용 시 제외하지 않는다 (정보 없음을 이유로 후보에서 빼지 않는다).

## 3. 프론트엔드 동작 계약

| 상황 | 데이터 소스 |
|---|---|
| 최초 진입 (기본 필터) | `regions.json` 만 |
| 평형 버킷 변경 | `regions.json` (버킷별로 이미 사전 계산됨) |
| 기간 변경 (전체/6개월/3개월) | `regions.json` |
| **건축년도 필터 적용** | `trades-*.json` 지연 로드 후 재계산 |
| **최소 거래건수 변경** | `regions.json` 의 `count` 로 필터 (지역 단위) / 단지 단위는 `trades-*.json` |
| **단지 검색** | `trades-*.json` 지연 로드 |
| 단지 상세 (개별 거래 내역) | `trades-*.json` |

- 지연 로드 중에는 로딩 상태를 표시하고, 로드 실패 시 기본 뷰는 유지한 채 오류를 알린다.
- 한 번 로드한 `trades-*.json` 은 메모리에 캐시하고 재요청하지 않는다.

---

## 4. 경기도 추가 시 변경점

경기 데이터가 붙으면 다음만 달라진다. 프론트엔드 코드 수정은 필요 없어야 한다.

1. `regions.json` 의 `regions` 배열에 `sido: "경기"` 항목 31개가 추가된다.
2. `meta.datasets` 에 `{ "sido": "경기", "file": "trades-gyeonggi.json", … }` 가 추가된다.
3. 프론트엔드는 `meta.datasets` 를 보고 지연 로드할 파일 목록을 **동적으로** 결정한다.
   파일명을 하드코딩하지 않는다.
